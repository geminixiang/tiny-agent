一句話掌握本章核心：取消（Cancellation）不是單純「把 Promise 拋棄」，而是必須遵循 先記 Abort 意圖再發送中斷信號 的順序。歷史壓縮（Compaction）則透過本文所稱的 雙切點（Two-Cut） 交易縮減 Active Context，同時保留原始 message facts 供復原與一致性稽核。

中斷的正確順序：先持久化意圖，再發送信號

設想情境：工程師在 bash deploy.sh 執行時按下了 Esc。如果系統直接呼叫 abortController.abort() 卻未先寫入磁碟，一旦行程在此刻崩潰，重啟後系統完全不知道使用者曾要求中斷，可能會誤判為未知錯誤而發起重試。 

# 概念偽碼。TypeScript 實際介面名稱是 session.append(...)
1. 持久化中斷意圖 ──→ append(abortRequested) 完成
                           ↓
2. 發送中斷信號   ──→ 向當前 Model API / Bash Child Process 傳遞 AbortSignal
                           ↓
3. 補齊結構化狀態 ──→ 將未完成的 Tool 標記為 interrupted，保持 Transcript 合法
                           ↓
4. 寫入終局記錄   ──→ append(operationFinished: aborted)
                           ↓
5. 釋放本次資源   ──→ 關閉 Session/連線。已完成 bg start 的行程需另行 bg stop 或由部署 supervisor 清理

Cancellation 依 Phase 精準分流

當前運行階段 (Phase)具體中斷動作 (Signal Action)Durable WAL 狀態修復 (Reconciliation)
Model Phase透過 AbortSignal 取消進行中的 Provider HTTP request將未結算的 Attempt 標記為 stepFailed(aborted)
Tool Phase將 AbortSignal 傳給當前 Tool。foreground bash 交由 Node child-process API 中斷。本路徑沒有通用的 TERM→grace→KILL process-tree supervisor。bg stop 是另一條具兩階段 signal 的管理路徑。已啟動的 Tool 補寫 interrupted。同一 assistant response 中尚未啟動的 calls 補寫 aborted
Compaction Phase中斷摘要生成請求關閉當前 Compaction Attempt，結束該 Operation

Abort Race 競爭條件的裁決鐵律

當使用者中斷與模型/工具回傳互相競爭時，關鍵不是牆鐘上的「同一毫秒」，而是 durable append 與 serialized settlement 的先後：

競爭勝出方判決條件最終歷史呈現
成功結算先完成，active 已解除結果已 append，且該 active operation 已由 settlement 清除後到的 Abort 找不到 active operation，不改寫既有結果。Runtime 可依既有狀態繼續。
abortRequested 先落盤中斷意圖已成功寫入 WAL遲到的成功回應一律作廢丟棄，該操作嚴格記錄為 aborted。

Compaction 歷史壓縮：雙切點（Two-Cut）架構

重要觀念：目前的 Compaction 不會從 Session JSONL 中刪除舊 message facts。它建立新的摘要節點（Checkpoint）來縮減 Active Context。這是現行格式行為，不代表跨備份、retention policy 或儲存媒體的「永存」承諾。

雙切點（Two-Cut）的嚴格定義

Schema 上刻意把「開始時鎖定的來源 partition」和「成功後產生的 checkpoint」分開：compactionStarted 是 durable intent 與 source digest。compaction entry 是 summary 結果與可直接重建 Active Context 的 retained tail。這讓每個欄位都有明確用途，也避免把審計欄位和模型摘要結果混在同一個節點。

切點維度主要服務對象運作機制與邊界保證
Track 1: Active-Context CutLLM 大腦（推論視窗）保留最近至少 6 則訊息，並自動向前尋找 user 邊界（避免拆散單次完整問答）。前次產生的舊 Summary 會參與本次新摘要的計算。
Track 2: Durable Source Partition一致性稽核與 Crash RecoverycompactionStarted 記錄 compactedEntryIds、retainedEntryIds 與 sourceDigest。compaction entry 則記錄 summary、compactedThroughEntryId 與 materialized retainedTail。Reducer 可偵測內容、順序或 partition 未同步更新。但未加密 SHA-256 不是 MAC/signature，能寫檔的攻擊者仍可重算，因此不構成 tamper-proof audit log。
